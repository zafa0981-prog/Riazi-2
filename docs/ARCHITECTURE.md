# معماری سایت «ریاضی دوم با فیلی»

## وضعیت مرحلهٔ ۱ (همین بسته)
سایت ایستا (HTML/CSS/JS) است و روی GitHub Pages اجرا می‌شود. بدون ابزار ساخت و بدون سرور.

| فایل | نقش |
|---|---|
| `index.html` | صفحهٔ معرفی |
| `chapters.html` | انتخاب هشت فصل (فصل ۳ تا ۸ با قفل طلایی) |
| `buy.html?ch=N` | معرفی فصل قفل‌دار (پرداخت هنوز غیرفعال است) |
| `affiliate.html`, `info.html` | همکاری در فروش، درباره/تماس/قوانین/حریم خصوصی (پیش‌نویس) |
| `config.js` | **تنها منبع** نام فصل‌ها و رایگان/قفل بودن |
| `access.js` | نقطهٔ کنترل دسترسی (فعلاً فقط `free` در config) |
| `ch1.html`, `ch2.html` + `gen.js`, `engine.js`, `style.css`, `snd.js` | فصل‌های رایگان |
| `a/` | تصاویر |

## محدودیت مهم GitHub Pages
GitHub Pages فایل ایستا می‌دهد؛ هیچ کد سمت سرور ندارد. بنابراین **کنترل دسترسی واقعی روی آن ممکن نیست**. هر فایلی که در مخزن عمومی باشد، با آدرسش برای همه قابل دانلود است. به همین دلیل:
- فایل‌های `ch3.html` تا `ch8.html` عمداً در بستهٔ عمومی نیستند و در zip خصوصی جدا هستند.
- قفل فعلی صرفاً رابط کاربری است و جلوی هیچ‌کس را نمی‌گیرد، چون خودِ فایل‌ها آنجا نیست.

## مسیر مرحلهٔ بعد (پیشنهاد، هنوز ساخته نشده)
1. **Supabase**: احراز هویت (ایمیل/موبایل)، پایگاه داده، Storage خصوصی.
2. فایل‌های فصل ۳ تا ۸ داخل Storage **خصوصی**؛ ارائه فقط از طریق Edge Function که ابتدا جدول `entitlements` را برای کاربر وارد‌شده بررسی می‌کند.
3. صفحهٔ فصل‌ها بعد از ورود، وضعیت خرید کاربر را از سرور می‌خواند. `chapterAccess()` در `access.js` همین‌جا عوض می‌شود.
4. **پرداخت**: ساخت سفارش در سرور، ارسال به درگاه (زرین‌پال)، و تأیید فقط با Verify سمت سرور. موفقیت هرگز از پاسخ مرورگر نتیجه‌گیری نمی‌شود. اطلاعات واقعی درگاه (merchant id) هنوز نداریم؛ پس پرداخت فعال نیست.
5. **پورسانت**: دفتر حساب (ledger) با شناسهٔ یکتا برای هر تراکنش تا جلوی ثبت/واریز تکراری گرفته شود. پیش‌نویس جدول‌ها: `schema-draft.sql`.
6. **واریز بانکی فوری** فقط با یک سرویس انتقال وجهِ مجاز و مستندات API رسمی ممکن است. جزئیات آن را من نمی‌دانم و باید از سرویس‌دهنده پرسیده شود. تا آن زمان کیف پول داخلی روش جایگزین است.
7. هاست این مرحله: GitHub Pages کافی نیست؛ برای Next.js با بک‌اند به Vercel یا Netlify (یا سرور خودت) نیاز داریم.
